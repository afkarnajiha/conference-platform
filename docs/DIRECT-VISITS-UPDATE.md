# تحديث التسجيل المباشر — دون مراجعة أو حجز

هذه حزمة تعديل للمشروع السابق وليست مشروعًا جديدًا. لا تغيّر ملف .env أو مفاتيح GitHub أو إعدادات النشر، ولا تحذف أي جدول. أدوار المشرف والمدير وإدارة الفريق والتقارير تبقى كما هي؛ الذي ألغي هو اعتماد المعرض وحجزه أثناء تعبئة الزيارة.

## التطبيق على الموقع الحالي

1. احفظ تعديلاتك الحالية في GitHub باستخدام Commit ثم Push. احتفظ بنسخة احتياطية من قاعدة البيانات قبل أي تحديث إنتاجي.
2. فك ضغط الحزمة. انسخ مجلد `src` إلى جذر مشروعك الحالي بجانب `package.json`، ووافق على استبدال الملفات الموجودة. الملفات الأخرى في `src` تبقى كما هي. إذا عدّلت بنفسك أحد هذه الملفات، قارن التغييرات قبل استبداله للحفاظ على تخصيصاتك.
3. انسخ أيضًا مجلدات `tests` و`.github` و`supabase` و`docs` من الحزمة إلى المشروع بالدمج، وليس بحذف المجلدات القديمة. لا تستبدل ملف `.env` أو `package.json` أو ملف القفل.
4. من Supabase افتح SQL Editor ثم New query. افتح `supabase/upgrade-direct-visits.sql` وانسخ محتواه كاملًا ثم اضغط Run. هذا التحديث مخصص لقاعدة البيانات التي طُبق عليها ملفا SQL الأصليان. لا تعِد تشغيل الملفين الأصليين.
5. في طرفية VS Code داخل المشروع نفّذ:

```powershell
npm.cmd test
node tests/direct-visits.mjs
npm.cmd run build
```

6. اعمل Commit وPush من VS Code. انتظر نجاح GitHub Actions ثم افتح الموقع واضغط Ctrl+Shift+R. يفضل تطبيق الخطوات في وقت لا يسجل فيه الموظفون زيارات، لأن الصفحات المفتوحة بالإصدار القديم ستحتاج تحديثًا.

لا يحتاج هذا التعديل إعادة نشر `manage-account` أو تغيير أسرار Supabase.

## السلوك الجديد

- الرمز المعروف يفتح نموذج الزيارة مباشرة، إذا لم تكن الزيارة مكتملة.
- الرمز الجديد يطلب اسم المعرض والجهة أو الربط بمعرض موجود، ثم يفتح النموذج دون اعتماد مشرف.
- جميع بيانات التواصل والنشاط والفرص والتقييم والصور وPDF باقية.
- لا حجز ولا عدّاد ولا انتهاء مهلة. إغلاق الصفحة دون حفظ قد يفقد المسودة؛ لا يوجد حفظ مسودة تلقائي.
- المعارض القديمة التي كانت تحتاج مراجعة أصبحت متاحة مباشرة.
- يستطيع موظفان فتح النموذج، لكن الحفظ داخل قاعدة البيانات يسمح بزيارة واحدة لكل جولة. يظهر تنبيه للثاني وتبقى بيانات نموذجه قابلة للنسخ.
- الإذن بزيارة إضافية من المدير يبقى متاحًا مع الاحتفاظ بالتاريخ.
- بيانات الحجوزات القديمة وجدولها لا تُحذف، لكنها لا تستخدم، والاستدعاءات القديمة للحجز معطلة. هذا يحافظ على البيانات ويمنع العملاء القدماء من إعادة تفعيل الحجز.

## التحقق

نجحت 29 حالة اختبار للواجهة والقواعد والتصدير، و10 فحوص SQL مخصصة لهذا التحديث، تشمل عدم إنشاء حجز، حفظ المرفقات دون رمز حجز، منع تكرار الحفظ، بقاء البيانات السابقة، وحماية هوية المستخدم. اختبارات SQL محلية عبر PGlite؛ لم يُطبّق التحديث على حساب Supabase الخاص بك من هذه المحادثة. اختبر بعد النشر بموظف ومعرض اختبار، وراجع فتح الملفات وظهور الزيارة في حساب آخر.

ملفات README وARCHITECTURE القديمة تصف الإصدار السابق؛ هذا الملف هو المرجع الأحدث لدورة الزيارة. للتثبيت الجديد مستقبلًا طبّق الملفين الأصليين ثم `upgrade-direct-visits.sql`.
