# تحليل النظام وخطة التنفيذ

المنصة مخصصة لشركة واحدة، وتدعم مؤتمرات متعددة. هوية المستخدم من Supabase Auth، وصلاحياته من profiles فقط. لا تُقرأ الصلاحيات من user_metadata. كل عملية تتطلب حسابًا نشطًا.

## الطبقات
واجهة React وTypeScript وTailwind؛ تنقل HashRouter يدعم تحديث الصفحة في GitHub Pages. Supabase Postgres للبيانات وRealtime، Auth للجلسات، Storage خاص للمرفقات، Edge Function لإدارة حسابات Auth. لا خادم آخر ولا Service Role في الواجهة.

## دورة الزيارة
QR الأصلي ← مطابقة نص مطابق بعد إزالة المسافات الطرفية ← معرض معروف أو طلب إنشاء/ربط ← حجز ذري لمدة 20 دقيقة ← مسودة نموذج ← رفع مرفقات خاصة ← حفظ ذري للزيارة والفرص والمرفقات ← اكتمال. لا يتم فتح روابط QR تلقائيًا، ولا يمثل فتح رابط زيارة.

تقفل جميع عمليات الحجز والحفظ وإعادة التعيين صف المعرض نفسه بـ SELECT FOR UPDATE. لكل معرض جيل visit_round؛ قيد UNIQUE(exhibition_id, visit_round) يمنع تكرار الزيارة. المدير وحده يستطيع زيادة الجيل مع سبب إلزامي، دون حذف تاريخ الشركة. الحجز يحتوي token لمنع نموذج قديم من الحفظ بعد إعادة التعيين. الانتهاء يعتمد على ساعة قاعدة البيانات، ولا يعتمد على إغلاق المتصفح.

## صلاحيات البيانات
الحسابات النشطة ترى جدول الفريق والمعارض والزيارات. الموظف يعدل زيارته فقط. المشرف يراجع كل الزيارات، ويدير المعارض والتوزيع. إدارة الموظفين تتطلب manage_employees أو دور المدير. المشرف لا يدير مشرفًا أو مديرًا. المدير الوحيد يدير المؤتمر وإعادة التعيين. لا توجد كتابة مباشرة على profiles أو visits أو الحجوزات أو الفرص؛ العمليات الحساسة عبر RPC أو وظيفة خادم.

## المرفقات
حد 10 ملفات للزيارة و10MB للملف؛ PNG/JPEG/WebP/PDF فقط. المسار user/exhibition/token/uuid.ext. لا حاوية عامة؛ روابط موقعة قصيرة العمر. RLS يسمح بالرفع لصاحب الحجز الفعال فقط، وبقراءة الملفات المرتبطة بزيارة للحسابات النشطة. يمكن حذف الملفات المؤقتة الخاصة بصاحبها. التحقق من توقيع الملف في المتصفح ومن MIME والحجم في Storage؛ فحص مضاد فيروسات ليس مدمجًا.

## المراحل ومعايير التحقق
1. SQL: القيود وRLS والحجز وحفظ الزيارة، اختبارات PostgreSQL محلية على PGlite مع محاكاة auth/storage، ثم اختبار تزامن حقيقي لاحقًا على Supabase.
2. الواجهة: المصادقة، لوحة التحكم، المعارض، المسح والنموذج، الفريق والتوزيع، التقارير والإعدادات.
3. التكامل: Realtime مع إعادة تحميل دورية، رفع الملفات، إدارة الحسابات بالخادم.
4. التسليم: بناء TypeScript/Vite، اختبارات وحدات، تعليمات التشغيل والنشر، قائمة التحقق الفعلية والمتبقية.

عدم وجود اتصال ليس قاعدة بيانات فارغة: تظهر حالة إعداد منفصلة، ولا تظهر أرقام مصطنعة. بيانات الإنتاج واختبارات المصادقة والكاميرا والتزامن عبر حسابين تؤجل حتى توفر مشروع Supabase والأجهزة الفعلية.
